SlideSight

Writes alt text for the pictures in PowerPoint lecture slides, saves only the descriptions it is sure of, and sends the rest to a person. Every model call runs on ASU hardware.

The problem

A blind student opening a lecture deck usually hears “Picture 4.” Sometimes it is worse. In one real ASU course deck the alt text is a Windows file path, so that is what the screen reader spells out:

What the student hears C:\Users\symbiosis\Desktop\IB2COM\box_fls.png

Fixing this by hand costs $3–4 per page in manual remediation. SlideSight finds every picture in a .pptx, writes a description for each one, and saves the descriptions back into the file. A browser app and a command-line tool run the same pipeline underneath.

What's different

Generating PowerPoint alt text with a vision model has been done before. Two things here have not.

It knows when it is unsure

The model rates its own confidence from 1 to 5 in the same request that writes the description. Only 4s and 5s go into the file. Anything lower is held back, with the model's reason attached, for a person to approve or rewrite.

Nothing leaves campus

Lecture slides are unpublished faculty work and can carry graded student material. Every model call goes to ASU Research Computing, never a commercial API.

A third behaviour mattered more than expected: logos and icons get empty alt text so screen readers skip them. One Stanford deck repeats a briefcase icon 37 times. Without this, a student hears “briefcase” 37 times in one lecture.

How it works

01Findextract.py

Walk every shape, including inside groups, with each slide's own text and notes.

02Describedescribe.py

One model call per picture: description, decorative flag, confidence, reason.

03Decideapply.py

Apply, silence, or hold for review.

04Write backapply.py

Save alt text into the file; strip leaked filenames.

05Auditwcag.py

Five accessibility checks, no model calls.

Three things that are easy to get wrong

  • Pictures hide inside groups. Looping over slide.shapes found 13 pictures in the first deck; recursing into groups found 15. A flat loop misses 13%.
  • Pictures carry their original filename. Some screen readers read Screenshot 2026-09-02 at 9.25.40 AM.png aloud. SlideSight deletes it.
  • Context is per slide, not per deck. Sending the whole deck made descriptions vaguer. Each picture gets its own slide's text plus one 200-word summary of the file.

Confidence came back as 5 for 238 pictures, 4 for 137, 3 for four and 2 for one. Writing 4s straight into the file is deliberate: requiring a 5 would send another 137 pictures, 36% of everything, to a person.

The gate was tested, not assumed. A Gaussian blur of radius 6 on a well-handled picture drops its score to 3; radius 14 drops it to 2. Both land in the review queue. Remediated files reopen in python-pptx, Keynote and LibreOffice with every description preserved byte for byte.

Silencing a picture is the dangerous decision

A bad description gets read by a person and fixed. A wrongly silenced picture disappears from the file, and by design nobody sees it again. The confidence gate protected descriptions; nothing protected this. So every silenced picture was checked by eye.

MIT's AI 101 deck had photographs of cats, dogs and a crawling baby marked decorative, on slides about supervised learning. In a machine learning course those animals are the lesson. A decorative verdict now has to pass two checks, and failing either sends the picture to a person:

12%of slide area: anything larger is held back
843distinct colours: the most any confirmed logo or icon used
3,324distinct colours: the fewest any teaching photo used

Size alone missed a dog photo covering 1% of a feature-extraction slide, where the photo was the raw data being taught. Counting colours caught it. Together the two checks move 11% of previously silenced pictures into review, and MIT's AI 101 now silences nothing.

What we have not proved

  • No screen reader has read a finished file. The XML is correct and three readers preserve it, but nobody has listened to VoiceOver or NVDA read one yet.
  • The model can still be fooled. An unreadable picture beside matching slide text can carry a wrong description past the gate.
  • Coverage is ten decks, two departments. The goal was 20–30 across five; the time went into the false-positive analysis instead.
  • PowerPoint itself is untested. Python-pptx, Keynote and LibreOffice are.
